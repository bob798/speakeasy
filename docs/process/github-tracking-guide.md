# GitHub 跟踪载体选型指南

> 目的：在 Speakeasy 项目里，遇到"待办、Bug、想法、方案"时，知道**该写到哪里**，避免散落在多个地方导致丢失或重复维护。

---

## 一、GitHub 上常见的 7 种"跟踪载体"

按是否能闭环（有无明确"完成"状态）排序：

| 类型 | 适合什么 | 能否闭环 | 能关联代码 |
|---|---|---|---|
| **Issue** | 单条任务 / Bug / 想法，可讨论可分配 | ✅ open / closed | ✅ `Closes #N` 自动关闭 |
| **Pull Request** | 代码变更评审 | ✅ merged / closed | ✅ 本身就是 |
| **Milestone** | 一组 issue/PR 的版本目标（如 V0.8） | ✅ 进度条 + 关闭 | 间接 |
| **Project (v2)** | 看板 / 表格视图，把 issue + PR 编排到 backlog/doing/done | ✅ | 间接 |
| **Discussion** | 论坛式问答、长方案讨论、社区互动 | ❌ 无关闭概念 | ❌ |
| **Wiki / `docs/`** | 长期文档、教程、规范 | ❌ | ❌ |
| **`TODO.md` / 仓内 markdown** | 个人草稿、临时清单 | 手动维护 | ❌ |

---

## 二、Speakeasy 推荐组合

```
ROADMAP.md       → 跨版本愿景（季度级），由 Human 维护
Milestone V0.8   → 本版本要做的 issue 集合
Issue            → 单条工作，方案讨论 + 验收清单
PR               → 实现 + Closes #N 自动关单
BUG_LOG.md       → 已修复 bug 的根因归档（也可改用 issue + label:bug）
TODO.md          → 还没成型的脑洞清单 / 短期未排期杂项
docs/            → 规范、ADR、架构、流程（本文件就在这）
```

## 三、什么时候用哪个 —— 决策指南

### ✅ 用 **Issue** 当：
- 工作有明确的"完成"状态（实现 / 验收）
- 需要讨论方案候选（A / B / C）
- 将来会有 PR 关联、需要溯源"为什么这样做"
- 多设备 / 多人协作（手机也能改 label、回复）
- 是 Bug，且需要追踪修复进度

### ✅ 用 **PR** 当：
- 代码已经写好或正在写，要合并
- PR body 里写 `Closes #6` 即可在合并时自动关闭对应 issue

### ✅ 用 **Milestone** 当：
- 想把多个 issue / PR 圈成一个版本目标（V0.8、V0.9）
- 想看版本完成进度条
- **可与 Issue / PR 同时使用，互补不冲突**

### ✅ 用 **Project (v2)** 当：
- 当前版本 issue 数 ≥ 10 条，列表已经看不过来
- 需要看板视图（todo / doing / review / done）
- 需要按"业务模块 / 优先级 / 负责人"等多维度筛选

### ✅ 用 **Discussion** 当：
- 是开放式问题，没有"完成"概念（如"V1 的方向感觉怎么样？"）
- 要做长篇技术分享 / 复盘

### ✅ 用 **`TODO.md`** 当：
- 是脑洞 / 灵感 / 杂项，还没值得开 Issue
- 是个人短期备忘（一两天就会处理掉）
- 一旦有人讨论或要开发，就升级为 Issue 并删除本地条目

### ✅ 用 **`BUG_LOG.md`** 当：
- 已经修完的 Bug，要归档根因 + 修复方案给后人看
- 不适合追踪"还没修"的 Bug —— 那是 Issue 的活

### ✅ 用 **`docs/`** 当：
- 是规范、流程、架构决策（ADR）、教程
- 长期有效、需要随代码版本化

## 四、为什么不该把所有东西塞 `TODO.md`

`TODO.md` 看似"零成本"，但代价是：

1. **没法闭环**：勾掉 / 删除是手动行为，容易漏
2. **没法关联 PR**：实现完没有自动关闭机制
3. **没法讨论**：方案 A/B/C 的选择只能写在 commit message 里，难追溯
4. **多设备麻烦**：手机改 markdown 不顺手
5. **状态不可见**：别人看仓库不知道哪些已开工、哪些已完成

→ 所以本项目把 `TODO.md` 退化为"脑洞缓冲区"，正经工作一律走 Issue。

## 六、决策速查表

| 我手上有... | 写到哪里 |
|---|---|
| 一个具体任务 / Bug / 改进，会去做 | **Issue** |
| 一组 Issue 想打包成版本目标 | **Milestone** |
| Issue 数量爆炸，需要看板 | **Project** |
| 灵感 / 脑洞 / 短期备忘 | **TODO.md** |
| 已经修完的 Bug，记录根因 | **BUG_LOG.md** |
| 跨版本的产品方向 | **ROADMAP.md** |
| 流程 / 规范 / 架构决策 | **docs/** |
| 代码已写好等合并 | **PR**（带 `Closes #N`） |
| 开放式讨论，没有完成态 | **Discussion** |
